# App Store 公開手順書

このアプリ（React + Vite の Web アプリ）を iPhone アプリとして App Store で公開するまでの手順です。
アプリ本体のコードはほぼそのまま使い、**Capacitor** という仕組みで iOS アプリの「殻」を被せて提出します。

> **全体像**
> 1. Apple Developer Program に登録する（本人の手続き・有料）
> 2. Capacitor で iOS プロジェクトを作る
> 3. Mac + Xcode でビルド・動作確認する
> 4. App Store Connect にアプリ情報を登録する
> 5. TestFlight で自分でテストする
> 6. 審査に出して、通れば公開

---

## 0. 先に決めておくこと

| 項目 | 内容 | 例 |
| --- | --- | --- |
| アプリ名 | App Store に表示される名前（全角・半角30字以内、他アプリと重複不可） | 暗記アプリ |
| Bundle ID | アプリの一意な識別子。あとから変更できない | `com.plematsu.memorizationapp` |
| 価格 | 無料 / 有料 | 無料 |
| AI 機能の扱い | 公開版で AI 問題作成を有効にするかどうか（→「6. AI 機能の注意点」参照） | まずは無効がおすすめ |

## 1. 費用

| 項目 | 金額 |
| --- | --- |
| Apple Developer Program 年会費 | 99米ドル／年（日本では Apple Developer アプリ経由で 12,800円／年） |
| アプリ公開そのもの | 無料（無料アプリの場合） |
| Mac | 手持ちがなければ別途必要（→「8. Mac がない場合」参照） |

年会費を払い続けないと、アプリは App Store から取り下げられます。

## 2. Step 1: Apple Developer Program に登録する

**このステップだけは本人でないとできません**（本人確認と支払いがあるため）。

1. iPhone に **Apple Developer** アプリをインストールする
2. 自分の Apple アカウントでサインインし、「今すぐ登録」から進む
3. 個人（Individual）として登録し、本人確認書類の撮影など画面の指示に従う
4. 年会費を支払う
5. 「アカウントが有効になりました」というメールが来たら完了（数時間〜1日程度かかることがあります）

登録できたら、以下の2サイトにログインできることを確認してください。

- https://developer.apple.com/account （証明書・Bundle ID の管理）
- https://appstoreconnect.apple.com （アプリの登録・提出）

## 3. Step 2: Capacitor で iOS アプリ化する

リポジトリのルートで実行します（Node.js が必要です）。

```bash
# 依存関係のインストール
npm install

# Capacitor の導入
npm install @capacitor/core @capacitor/ios
npm install -D @capacitor/cli

# 初期化（appId は Step 0 で決めた Bundle ID、webDir は dist）
npx cap init "暗記アプリ" com.plematsu.memorizationapp --web-dir=dist

# iOS プロジェクトの追加
npx cap add ios
```

その後、コードを変更するたびに次を実行するとアプリ側に反映されます。

```bash
npm run build
npx cap sync ios
```

### アイコンの用意

- **1024 × 1024 px・透過なし（PNG）** のアイコン画像を1枚用意します
- Xcode の `Assets.xcassets > AppIcon` にその画像を置けば、各サイズは自動生成されます

### このアプリ固有の確認ポイント

- **読み上げ機能**: Web Speech API（`speechSynthesis`）を使っています。実機で声が出るか必ず確認してください
- **データ保存**: 学習データは端末内（localStorage）に保存されます。アプリを削除するとデータも消えます。その旨をアプリ説明文に書いておくと親切です
- **AI 機能**: 設定（`.env`）が空なら AI パネルは「未設定」と表示され、他の機能はそのまま使えます。公開版ではまずこの状態で出すのが安全です（理由は「6.」参照）

## 4. Step 3: Xcode でビルド・動作確認する

1. Mac に **Xcode**（Mac App Store から、無料）をインストールする
2. プロジェクトを開く

   ```bash
   npx cap open ios
   ```

3. Xcode 左上の対象プロジェクトを選び、**Signing & Capabilities** タブで
   - 「Automatically manage signing」にチェック
   - Team に自分の Apple Developer アカウントを選ぶ
4. 自分の iPhone を Mac に接続し、実行ボタン（▶）で実機にインストールして動作確認する
   - チェック項目: 問題集の作成 / 4つの問題形式 / 学習・採点 / 達成度の表示 / 読み上げ / アプリ再起動後にデータが残っているか

## 5. Step 4: App Store Connect に登録する

https://appstoreconnect.apple.com で行います。

1. **マイ App → ＋ → 新規 App** でアプリを作成（プラットフォーム iOS、名前、Bundle ID、SKU は適当な文字列で OK）
2. **アプリ情報**を入力する
   - カテゴリ: 教育
   - 年齢レーティング: 質問票に答える（このアプリは通常「4+」になります）
3. **価格と販売状況**: 価格を「無料」に設定
4. **App のプライバシー**
   - **プライバシーポリシーの URL が必須**です（データ収集をしていなくても必要）。GitHub Pages などに簡単なページを置く方法があります
   - データ収集の申告: AI 機能を無効にした状態なら「データを収集していません」と申告できます
5. **ストア掲載情報**
   - 説明文、キーワード、サポート URL
   - **スクリーンショット**: iPhone 用（6.9インチ: 1320 × 2868 px など）。Xcode のシミュレータで撮影できます。最低1枚、実際は3〜5枚あると良いです

## 6. AI 機能の注意点（公開版で有効にしたい場合）

API キーをアプリの中に埋め込むと、**誰でもキーを取り出して使えてしまいます**。
公開版で AI 問題作成を有効にしたい場合は、次のどちらかが必要です。

- **案A（推奨）**: API キーを保持する小さなサーバーを別に用意し、アプリはそのサーバー経由で AI を呼ぶ。`src/ai/provider.ts` の接続先をそのサーバーに向けるだけです（この分離は最初から意識して作ってあります）
- **案B**: 利用者自身に自分の API キーを入力してもらう形式にする

特に理由がなければ、最初の公開は **AI 機能オフ** で出し、慣れてから案Aで追加するのがおすすめです。

## 7. Step 5〜6: TestFlight テストと審査提出

1. Xcode で **Product → Archive** を実行する
2. Organizer が開いたら **Distribute App → App Store Connect → Upload** でアップロードする
3. App Store Connect の **TestFlight** タブにビルドが表示されたら（処理に数分〜数十分）、まず自分の iPhone でインストールして最終確認する
4. 問題なければ App Store Connect でそのビルドを選び、**審査へ提出**する
5. 審査は数日かかることが多いです。通過すれば自動（または手動）で公開されます

### 審査で落とされやすいポイントと対策

| ポイント | 対策 |
| --- | --- |
| **ガイドライン 4.2**（Web サイトを表示するだけのアプリは不可） | このアプリは端末内で完結して動作する学習アプリです。審査メモ（App Review へのメモ欄）に「オフラインで動作すること」「問題作成・学習・記録がアプリ内で完結すること」「審査手順（問題集を作って解く流れ）」を英語で書いておく |
| 動作しない機能がある | AI 機能が未設定表示のままなら、その旨も審査メモに一言書く（「AI 機能は任意設定で、未設定でも全機能が使える」など） |
| プライバシー申告の不一致 | 実際に通信する内容と申告を一致させる |

リジェクトされても、指摘に対応して再提出すれば大丈夫です。一度で通らなくても珍しくありません。

## 8. Mac がない場合

最終ビルドと提出には Xcode（Mac 専用）が必要です。Mac がない場合は次の代替があります。

- **クラウドビルドサービス**（Codemagic、Expo Application Services など）: GitHub リポジトリと連携してクラウド上の Mac でビルドし、App Store Connect へ提出までできます。無料枠があるサービスもあります
- **Mac レンタルサービス**（MacinCloud など）: 時間貸しの Mac をリモートで使う

## 9. 公開後の更新の流れ

1. コードを修正する
2. `npm run build` → `npx cap sync ios`
3. Xcode でバージョン番号（例: 1.0 → 1.1）を上げる
4. Archive → アップロード → 再度審査に出す

小さな修正でも、原則として毎回審査が必要です。
